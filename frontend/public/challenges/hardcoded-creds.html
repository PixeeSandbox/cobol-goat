🎓 Security Notes

The COBOL login program stores administrator credentials as literal VALUE constants in the WORKING-STORAGE SECTION. These values are embedded in the compiled binary and visible in the source code. Anyone with access to the source or binary can extract them.

LOGIN.cbl — COBOL 85 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. LOGIN.

       WORKING-STORAGE SECTION.
       *> Credentials hardcoded as VALUE literals
       01  WS-ADMIN-CREDENTIALS.
           05  WS-ADMIN-USER    PIC X(10) VALUE 'admin'.
           05  WS-ADMIN-PASS    PIC X(12) VALUE 'c0b0ladm1n'.
           05  WS-ADMIN-ROLE    PIC X(10) VALUE 'ADMIN'.

       PROCEDURE DIVISION.
       MAIN-PARA.
           MOVE 'FAIL' TO WS-AUTH-RESULT
           IF  WS-INPUT-USER = WS-ADMIN-USER
           AND WS-INPUT-PASS = WS-ADMIN-PASS
               MOVE 'PASS' TO WS-AUTH-RESULT
               GO TO AUTH-SUCCESS
           END-IF.

Look at the COBOL source above. The WORKING-STORAGE SECTION contains a group item called WS-ADMIN-CREDENTIALS. Each PIC X(n) VALUE '...' clause sets a fixed string literal at compile time.

What are the values of WS-ADMIN-USER and WS-ADMIN-PASS?

The Vulnerability

Credentials hardcoded in COBOL WORKING-STORAGE are embedded in the compiled object code and visible in the source. Anyone with access to the source or compiled binary can extract them with a strings command or code review.

Exploit

Login with: Username: admin  /  Password: c0b0ladm1n

Fix

  • Never store credentials in source code or compiled binaries
  • Use environment variables or a secrets manager (HashiCorp Vault, AWS Secrets Manager)
  • In COBOL: read from a secured parameter dataset or call an external credential service at runtime
  • Rotate any exposed credentials immediately
