Select a report type and delivery address to generate and distribute financial summaries.

Report Generator

Shell Command Being Constructed
generate_report.sh monthly | mail -s 'Report' user@example.com
Sample Inputs
  • monthly; cat /etc/passwd Semicolon separator — reads passwd file
  • monthly; id; whoami Reveal process user identity
  • monthly; ls -la / List root filesystem contents
Command Output
🎓 Security Notes

The COBOL report generator passes user-controlled input directly to CALL 'SYSTEM', which executes a shell command. An attacker can inject additional OS commands using shell metacharacters like ;, $(...), or backticks.

REPORT.cbl 
       WORKING-STORAGE SECTION.
       01  WS-REPORT-TYPE       PIC X(50).
       01  WS-EMAIL             PIC X(100).
       01  WS-COMMAND           PIC X(200).

       PROCEDURE DIVISION.
       GENERATE-REPORT.
           *> Unsanitized user input passed to SYSTEM
           STRING
               "generate_report.sh "
               WS-REPORT-TYPE
               " | mail -s 'Report' "
               WS-EMAIL
               INTO WS-COMMAND
           END-STRING
           CALL 'SYSTEM' USING WS-COMMAND.

The shell interprets ; as a command separator. If you provide monthly; cat /etc/passwd as the report type, the shell runs two commands:

  1. generate_report.sh monthly
  2. cat /etc/passwd

The output of both commands is returned.

Impact

OS command injection gives the attacker full shell access under the COBOL process's user account. They can read files, exfiltrate data, install malware, or pivot to other systems.

Fix

  • Never pass user input to CALL 'SYSTEM' or any shell execution function
  • Whitelist allowed report types with a lookup table — no free-form input
  • If OS invocation is necessary, use an API that separates arguments from the command name
  • Run the COBOL process under a minimal-privilege service account
