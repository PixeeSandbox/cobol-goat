🎓 Security Notes

The COBOL search program builds SQL queries with no sanitization. User input is concatenated directly into a LIKE clause, allowing UNION-based injection to pivot to any table in the database.

SEARCH.cbl 
       WORKING-STORAGE SECTION.
       01  WS-SEARCH-TERM       PIC X(200).
       01  WS-SEARCH-SQL        PIC X(500).

       PROCEDURE DIVISION.
       BUILD-SEARCH-QUERY.
           *> User input concatenated into LIKE clause
           STRING
               "SELECT id, name, price, category, stock"
               " FROM products WHERE name LIKE '%"
               WS-SEARCH-TERM
               "%'"
               INTO WS-SEARCH-SQL
           END-STRING
           EXEC SQL
               EXECUTE IMMEDIATE :WS-SEARCH-SQL
           END-EXEC.

The SELECT returns 5 columns: id, name, price, category, stock.

For a UNION injection, your injected SELECT must also return 5 columns. Try:

%' UNION SELECT username,password,role,4,5 FROM users --

The -- comments out the trailing %' that would otherwise break the syntax.

Impact

UNION-based injection lets an attacker read any table in the database — user credentials, financial data, session tokens, anything accessible to the DB user. A DROP injection can destroy tables.

Fix

  • Use parameterized queries / prepared statements (DB2 parameter markers)
  • Whitelist allowed characters in search input (alphanumeric + limited punctuation)
  • Apply least-privilege DB accounts — the search function should never have access to the users table
  • Enable DB2 audit logging to detect injection attempts
