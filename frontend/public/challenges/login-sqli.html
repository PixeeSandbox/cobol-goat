🎓 Security Notes

The COBOL login program builds the SQL authentication query by direct string concatenation using the STRING verb. User input flows directly into the query with no parameterization or escaping.

LOGINDB.cbl — COBOL/DB2 
       WORKING-STORAGE SECTION.
       01  WS-SQL-QUERY         PIC X(500).
       01  WS-USERNAME          PIC X(50).
       01  WS-PASSWORD          PIC X(50).

       PROCEDURE DIVISION.
       BUILD-AUTH-QUERY.
           *> Raw string concatenation — no parameterization
           STRING
               "SELECT * FROM users WHERE username='"
               WS-USERNAME      DELIMITED SPACE
               "' AND password='"
               WS-PASSWORD      DELIMITED SPACE
               "'"
               INTO WS-SQL-QUERY
           END-STRING
           EXEC SQL
               EXECUTE IMMEDIATE :WS-SQL-QUERY
           END-EXEC.

The SQL template is: SELECT * FROM users WHERE username='INPUT' AND password='INPUT'

If you enter admin' OR '1'='1 as the username, the final query becomes:

SELECT * FROM users WHERE username='admin' OR '1'='1' AND password=''

Since OR '1'='1' is always true, the WHERE clause returns all rows. The first row is typically the admin account.

The Vulnerability

The COBOL program uses STRING to concatenate user input directly into an SQL statement, then executes it with EXECUTE IMMEDIATE. The attacker can manipulate the query logic by embedding SQL syntax into the input.

Fix — Use Parameter Markers (DB2)

Fixed version
       EXEC SQL
           PREPARE STMT FROM
             'SELECT * FROM users WHERE username=? AND password=?'
           EXECUTE STMT USING :WS-USERNAME, :WS-PASSWORD
           INTO :WS-RESULT
       END-EXEC
