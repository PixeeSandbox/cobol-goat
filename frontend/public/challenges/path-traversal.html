🎓 Security Notes

The COBOL file-read program concatenates user input directly into the file path used in an OPEN INPUT statement. Using ../ sequences an attacker can escape the base directory and read sensitive server files.

FILEREAD.cbl 
       WORKING-STORAGE SECTION.
       01  WS-BASE-PATH  PIC X(50) VALUE '/opt/cobol/data/reports/'.
       01  WS-USER-INPUT PIC X(100).
       01  WS-FILE-PATH  PIC X(150).

       PROCEDURE DIVISION.
       OPEN-FILE.
           *> No canonicalization or traversal check
           STRING
               WS-BASE-PATH    DELIMITED SPACE
               WS-USER-INPUT   DELIMITED SPACE
               INTO WS-FILE-PATH
           END-STRING
           OPEN INPUT INPUT-FILE.

The base path is /opt/cobol/data/reports/ — four directories deep. Using ../../etc/passwd resolves to /opt/cobol/data/etc/passwd, not deep enough. Try ../../../../etc/passwd to reach the root. Count the components: /opt(1) /cobol(2) /data(3) /reports(4) → need four ../.

Impact

Path traversal lets an attacker read any file the COBOL process can access: /etc/passwd, SSH keys, application config files with secrets, other users' data files, and more.

Fix

Fix option 1 — canonicalize and check prefix
       CALL 'realpath' USING WS-FILE-PATH WS-CANONICAL
       IF WS-CANONICAL(1:LENGTH(WS-BASE-PATH))
           NOT = WS-BASE-PATH
           MOVE 'ACCESS DENIED' TO WS-ERROR
           STOP RUN
       END-IF
Fix option 2 — whitelist exact filenames
       EVALUATE WS-USER-INPUT
           WHEN 'monthly'  MOVE 'monthly.txt' TO WS-FILE-PATH
           WHEN 'annual'   MOVE 'annual.txt'  TO WS-FILE-PATH
           WHEN OTHER      MOVE 'INVALID'     TO WS-ERROR
       END-EVALUATE
