Error Response
🎓 Security Notes

The server returns full stack traces, internal file paths, DB connection strings, and runtime configuration in error responses. An attacker can deliberately trigger errors to enumerate the server's internal architecture.

server.js — Global error handler 
       // VULNERABILITY: Global error handler exposes internals
       app.use((err, req, res, next) => {
         res.status(500).json({
           error:   err.message,
           stack:   err.stack,          // Full call stack
           file:    err.filename,       // Server file paths
           db:      process.env.DB_URL,  // DB connection string!
           cwd:     process.cwd(),       // Working directory
           version: process.version,    // Node version
         });
       });

Submit the form with the default (bad) values. Any input that crashes the server-side handler will trigger the verbose error response that leaks internal details including the DB connection string.

What Leaks

  • Full server-side stack traces (file paths, line numbers, function names)
  • DB connection strings including credentials
  • Server working directory structure
  • Node.js version (fingerprinting for known vulnerabilities)

Fix

Fixed version — generic error response
app.use((err, req, res, next) => {
  // Log internally with full details
  logger.error({ err, req });
  // Send generic message to client — NOTHING else
  res.status(500).json({ error: 'Internal Server Error' });
});
