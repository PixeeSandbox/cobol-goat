System Activity Logs

Monitor authentication events and application activity. Log entries are written by the COBOL logging module.

👤

Step 1 — Generate a Login Event

Submit a login to create an authentication log entry.

📄

Step 2 — View Authentication Log

Endpoint: GET /api/debug/logs — accessible to any authenticated user.

Log File: /var/log/cobolapp.log
🎓 Security Notes

The COBOL logging module writes the full login event — including the plaintext password — to a log file. Log files are regularly archived, emailed to ops teams, indexed by SIEM tools, and sent to log aggregators.

LOGGER.cbl 
       WORKING-STORAGE SECTION.
       01  WS-LOG-FILE  PIC X(50) VALUE '/var/log/cobolapp.log'.
       01  WS-LOGIN-PASS PIC X(50).  *> DANGER!

       PROCEDURE DIVISION.
       WRITE-LOGIN-LOG.
           STRING
               WS-TIMESTAMP        DELIMITED SIZE
               ' LOGIN user='      DELIMITED SIZE
               WS-LOGIN-USER       DELIMITED SPACE
               ' pass='            DELIMITED SIZE
               WS-LOGIN-PASS       DELIMITED SPACE
               ' result=OK'        DELIMITED SIZE
               INTO WS-LOG-ENTRY
           END-STRING
           WRITE LOG-RECORD FROM WS-LOG-ENTRY.

Step 1: Log in with any credentials — this creates a log entry. Step 2: Click "View Log File" to read the log. The log includes the pass= field in plaintext next to every login event.

Impact

Plaintext passwords in logs have a very wide blast radius — archived logs, SIEM ingestion, ops email, third-party aggregators. A leaked log exposes every user who logged in.

Fix

  • Never log passwords, tokens, SSNs, credit card numbers, or other secrets
  • Log the authentication outcome only (success/failure + username)
  • Apply log masking at the framework level so any field named "password" is auto-redacted
  • Restrict log file permissions — only the application service account should write
