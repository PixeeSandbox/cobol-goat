🎓 Security Notes

COBOL's fixed-point arithmetic silently truncates results that exceed the PIC clause width — no exception, no error, no warning. This can corrupt financial calculations silently.

INTEREST.cbl 
       WORKING-STORAGE SECTION.
       *> PIC 9(10)V99: max value = 9,999,999,999.99
       *> If result exceeds this, COBOL SILENTLY TRUNCATES
       01  WS-PRINCIPAL     PIC 9(10)V99.
       01  WS-RESULT        PIC 9(10)V99.  *> Same limit — will overflow!
       01  WS-TEMP          PIC 9(20)V99. *> Should use this for intermediate

       PROCEDURE DIVISION.
       COMPUTE-INTEREST.
           *> No ON SIZE ERROR clause — silent overflow
           COMPUTE WS-RESULT = WS-PRINCIPAL *
               (1 + WS-INTEREST-RATE) ** WS-YEARS.

Try Principal = $99,999,999, Rate = 15%, Years = 30.

The true result is approximately $66 trillion. A PIC 9(10)V99 field can only hold up to $9,999,999,999.99. COBOL silently keeps only the rightmost digits — the bank account shows a small corrupted number with no warning.

Impact

Silent truncation in financial systems is catastrophic — balances, interest charges, and transaction amounts can silently wrap to small or negative values. COBOL historically caused real-world banking errors because of this.

Fix

  • Always use ON SIZE ERROR clause on COMPUTE statements involving money
  • Use intermediate variables with extra-wide PIC clauses for intermediate results
  • Validate input ranges before computation to prevent known-overflow conditions
  • Add unit tests that verify boundary conditions for all financial calculations
