Configuration Values
🎓 Security Notes

Database passwords, API keys, and encryption keys are hardcoded as VALUE literals in COBOL WORKING-STORAGE. These get compiled into the object code and can appear in core dumps, memory dumps, and swap files.

CONFIG.cbl 
       WORKING-STORAGE SECTION.
       01  WS-DB-CONFIG.
           05  WS-DB-HOST    PIC X(50) VALUE 'db.internal.corp'.
           05  WS-DB-USER    PIC X(20) VALUE 'dbadmin'.
           05  WS-DB-PASS    PIC X(30) VALUE 'Pr0d$ecr3tDB!2024'.

       01  WS-API-CONFIG.
           05  WS-STRIPE-KEY PIC X(60) VALUE 'sk_live_EXAMPLE_4xKj8mN...'.
           05  WS-JWT-SECRET PIC X(40) VALUE 'jwt_s3cr3t_n0b0dy_kn0ws'.
           05  WS-AES-KEY    PIC X(32) VALUE 'AES256KeyHardcod3dInSource!!'.

Just click "Load Configuration". There is no exploit here beyond recognizing that an unauthenticated config endpoint returns secrets straight from the COBOL binary's WORKING-STORAGE values.

Impact

An attacker who reads these values gains: direct DB access, ability to forge Stripe charges, ability to send phishing emails via SendGrid, ability to forge JWT tokens for any user, and ability to decrypt any AES-encrypted data.

Fix

  • Use a secrets manager — HashiCorp Vault, AWS Secrets Manager, or Azure Key Vault
  • In COBOL: call an external credential provider at startup; store nothing in WORKING-STORAGE
  • Use environment variables as a minimum — never literal VALUES in source
  • Run git-secrets or trufflehog pre-commit to prevent secrets reaching source control
  • Remove or properly secure the /api/config endpoint
